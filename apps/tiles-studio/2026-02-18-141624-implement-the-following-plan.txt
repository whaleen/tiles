⏺ Here's what I found after reviewing the full UX flow:

  ---
  1. Descriptions Are Too Terse

  The API action list and in-form descriptions are written for someone who
  already knows the CLI. Some examples:

  Current: "Re-encode videos to fix CFR issues"
  Problem: What is CFR? Why would I need this?
  ────────────────────────────────────────
  Current: "Trim first frame from videos (fix black frame)"
  Problem: Sounds like it only trims 1 frame — actually trims N seconds
  ────────────────────────────────────────
  Current: "Clean and rename video files in folders"
  Problem: Clean how? Rename to what?
  ────────────────────────────────────────
  Current: "Random tile render with no parameters"
  Problem: What does "random" mean here?
  ────────────────────────────────────────
  Current: "Detect scene changes in videos"
  Problem: And then what? Splits them? Just lists them?

  The action descriptions live in two places:
  - actions.rs — the one-liner shown in the action list/dropdown
  - Each form component — the <p> inside the form body (some forms have none at
  all: concat, trim, detect, clean have zero in-form explanation)

  2. Single Video Actions: Mostly Works, But Rough

  The library flow is solid: select videos in the grid → LibraryActionPanel
  appears → pick action → targets are pre-populated. That works for single or
  multiple videos.

  But the Actions page flow for folders_or_videos actions shows this:

  Or enter video paths (comma-separated)
  [project/video1.mp4, project/video2.mp4]


  That's a raw text input. No one should have to type a path. The library is the
   right place for single-video workflows, but:

  - The library action dropdown shows raw slugs (doctor-reencode, strip-audio)
  not human names
  - There's no description shown in the dropdown — user has to pick blindly
  - The action panel doesn't show which actions support videos vs folders-only

  3. Output Mode Labels Are Confusing

  Current labels in ActionFormWrapper:

  Value: source
  Label: "Source (in-place outputs)"
  Problem: Users will think "in-place" means overwriting
  ────────────────────────────────────────
  Value: global
  Label: "Global outputs/"
  Problem: Outputs where? What folder?
  ────────────────────────────────────────
  Value: custom
  Label: "Custom output path"
  Problem: Forces path typing
  ────────────────────────────────────────
  Value: overwrite
  Label: "Overwrite originals"
  Problem: No confirmation, no warning

  The source mode actually creates a {source}/outputs/ subfolder next to the
  originals — that's the safest default but the label implies destructive
  behavior.
